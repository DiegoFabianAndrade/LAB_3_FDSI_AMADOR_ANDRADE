2. Nivel 1 — “Strings are evidence” · 15 puntos

Primero ejecuta el programa con datos falsos. Después observa sin asumir.

chmod +x crackme_level1
./crackme_level1
./crackme_level1 prueba

strings -n 5 crackme_level1 | less
objdump -d -M intel crackme_level1 | less
No busques la FLAG directamente. Busca primero qué dato compara el programa antes de llegar al camino de éxito.

3. Nivel 2 — Ghidra: reconstruir la validación · 25 puntos

  1. Crea un proyecto Non-Shared en Ghidra.
  2. Importa crackme_level2.
  3. Acepta el análisis automático.
  4. Ubica main y sigue la llamada que decide si la licencia es válida.
  5. Renombra variables y funciones según lo que deduzcas.
  6. Escribe pseudocódigo propio del algoritmo.
# Complemento fuera de Ghidra
strings -n 5 crackme_level2
objdump -d -M intel crackme_level2 | less
objdump -s -j .rodata crackme_level2 | less
Compara el índice del carácter con el índice de un pequeño arreglo que se reutiliza cíclicamente.
La operación central es reversible y trabaja byte a byte. Observa el operador que aparece antes de comparar el valor transformado con el arreglo esperado.

4. Confirmación dinámica con GDB · 15 puntos

No se trata de “adivinar”; se trata de demostrar en ejecución que tu hipótesis está bien.

gdb ./crackme_level2

# Dentro de GDB:
set disassembly-flavor intel
break validate_key
run AAAA
disassemble validate_key
info registers
continue
quit

Después repite con tu clave candidata y observa cómo cambia el retorno de la función.

5. Boss Level — binario sin símbolos · 10 puntos

Ahora abre crackme_level2_stripped. Ya no debes depender de nombres como validate_key.

file crackme_level2_stripped
nm crackme_level2_stripped
strings -n 5 crackme_level2_stripped
objdump -d -M intel crackme_level2_stripped | less

🌐 Módulo opcional — 20–30 min con Burp Suite

Burp no reemplaza a Ghidra: Burp analiza tráfico HTTP; Ghidra/GDB analizan el binario. Para incorporar Burp sin depender de publicar servicios, usa exclusivamente los laboratorios deliberadamente vulnerables de PortSwigger Web Security Academy.

Ruta sugerida: abre el tutorial oficial, mira los videos de introducción y practica únicamente Proxy → Intercept → Repeater sobre el laboratorio asignado.

  1. Inicia Burp Community.
  2. Usa el navegador integrado de Burp.
  3. Abre únicamente el laboratorio de Academy asignado.
  4. Intercepta una petición.
  5. Envíala a Repeater.
  6. Cambia un parámetro inocuo y observa request/response.
  7. Captura evidencia y explica qué diferencia hay entre análisis web y reverse engineering.

  4. Cómo la confirmó en ejecución.
